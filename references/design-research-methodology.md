# Design Research Methodology

Use in Phase 2 of a new, substantial project, before any concept is designed.

## Goals

Find what is genuinely current and excellent for this product category, learn why it works, and gather ideas to adapt. The output feeds three distinct concepts. It is inspiration, never a template to copy.

## Step 1: Frame the research

Write down: product category, audience, platform, tone adjectives, and three questions the research should answer (for example "how do top developer-tool sites present code on the hero?", "what navigation do modern finance dashboards use on mobile?").

## Step 2: Search angles

Run several searches, each from a different angle. Use the current year in queries only when you know the date. Cover:

- Latest UI/UX trends for this product category.
- Award-winning websites or apps in this category (recent winners, site of the day or month).
- Recently launched digital products in the category.
- Modern SaaS, dashboard or mobile interface designs relevant to the project.
- Advanced animation and interactive experiences that fit the tone.
- Typography trends and notable typeface releases.
- Color system approaches (palettes, dark-mode strategies).
- Layout and visual hierarchy techniques.
- Navigation and interaction patterns.
- New frontend libraries and web platform features (view transitions, scroll-driven animation, container queries, anchor positioning).

Scale effort to the project: a landing page needs fewer searches than a complex multi-role platform.

## Step 3: Sources

Inspiration sources (not restrictions): Awwwards, Dribbble, Behance, Godly, SiteInspire, Land-book, Mobbin. Also consider: Httpster, Lapa Ninja, Screenlane, Page Flows, Refero, Siteinspire, CSS Design Awards, FWA, Minimal Gallery, Typewolf (typography), Coolors or Realtime Colors (palettes), company design blogs, product changelogs, and the live sites themselves.

Source availability changes. Use whatever is currently active and reachable. Many gallery sites block automated access or load content with JavaScript; if a page returns nothing useful, say so and try another source instead of inventing details.

## Step 4: Inspect and verify

For each promising reference:

1. Open the real page if tools allow (fetch the URL).
2. Check the publication or launch date. Do not call it recent without evidence.
3. Note concrete visual traits: grid, type scale, palette, spacing, imagery treatment, component style.
4. Note motion and interaction: scroll behavior, hover, transitions, page changes.
5. Name why it works for its users.
6. Record the URL.

Never claim to have inspected a site you could not open. Label the evidence level honestly: "opened and read", "search snippet only", or "described by user".

## Step 5: Separate trends from clichés

Mark each idea as one of: **emerging** (distinct, increasingly used), **established** (mature and reliable), **overused** (recognizably generic, avoid by default). Widespread, instantly recognizable AI-template looks (purple gradients, uniform glass cards, centered hero with floating blobs) are overused unless the project truly calls for them.

## Step 6: Research summary format

Keep it short and scannable. A table works well:

| Reference | Link | Visual traits | Motion / interaction | Adapt for this project |
|---|---|---|---|---|

Follow with 3 to 5 bullets: the trends worth using, the clichés to avoid, and the opportunities that will make this project distinctive. Then move to concepts.

## If web access is unavailable

State it at the start: "I can't browse here, so this is not live research." Then ask the user to share reference URLs or screenshots, or to enable browsing. If the user wants to continue anyway, proceed with directions labeled "from general knowledge, unverified" and avoid naming specific recent sites as if you had checked them.

## Ethics

Learn principles, structures and techniques. Do not reproduce another site's layout, copy, imagery, code or distinctive visual identity. Every concept must be original.
